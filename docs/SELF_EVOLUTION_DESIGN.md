# 证据约束的学习与演进设计

本文定义 AI Investment Manager 的长期自演进协议。它不是自动写代码平台，也不是第二套投资系统，而是约束持续开发如何从现实结果中学习、如何避免反复试验制造虚假盈利，以及什么证据可以改变未来资本权限。未进入类型模型、持久化、现役查询、独立 evaluator、权限链和故障测试的条款仍只是设计，不能被页面或 Agent 描述为已有能力。

## 1. 唯一目标与边界

演进只优化同一 Mandate 下长期费用后、风险调整的总组合资本结果。单一资产 PnL、Forecast 分数、文字解释、调用次数、交易次数、实验通过率和代码提交量都不能替代该目标。

AI 可以定位问题、提出假设、实现候选并参与投资链中的任何角色，但不能选择自己的样本、修改自己的考试后晋级、解释自己的输出为通过结果，或绕过 Portfolio、Risk、Execution 和有效权限。没有足够证据时，`NO_CHANGE` 是完整决策。

系统只有一条学习关系：

```text
不可变业务事实与 Outcome
        ↓
首个可验证断点
        ↓
预登记的领域评价合同 + 最小候选
        ↓
未来样本或合法保留样本
        ↓
独立领域 evaluator
        ↓
删除、保留、限权、扩权或撤权
        ↓
只改变未来行为
```

这条关系不建立独立的“演进状态机”。开放评价义务由已登记合同及其尚不存在的终态结果派生；运行恢复复用原身份，不能通过重试生成新实验。

## 2. 唯一事实与最小治理对象

Evidence、State、WorldModel、Forecast、PortfolioTarget、RiskDecision、订单、成交、账户和 Outcome 继续由原领域拥有。评价器只读取这些不可变事实，不复制学习数据库、文本记忆或第二套 PnL。

长期只需要以下治理语义：

| 语义 | 作用 | 不拥有的内容 |
|---|---|---|
| 领域行为身份 | 标识某一领域会改变输出分布的模型、Prompt、Schema、输入、工具和政策 | 全局系统版本与部署进程 |
| 领域评价合同 | 在结果前冻结一个问题的样本、基线、统计规则和终态 | 其他领域的空字段 |
| 领域评价结果 | 由唯一 evaluator 回答一个问题 | 候选自报结论与通用指标袋 |
| `Authorization` | 把适用结果转换为有限、可撤销的运行或资本权限 | Alpha 计算与账户状态 |
| `ReleaseManifest` | 冻结实际部署内容并支持恢复 | 投资行为成绩 |
| Agent 证据视图 | 按任务从现役事实派生的点时内容引用 | 持久状态、指标重算、自由文本经验库 |

可检索评价目录由各领域合同和结果确定性派生，只投影评价类型、稳定 ID、内容哈希、作用域、评价家族、状态和废止引用，不接受独立写入。Dashboard、Agent 和 Authorization 引用同一领域结果，不能各自筛样本或产生另一份结论。

不建立通用 `LearningMemory`、`Reflection`、万能 `EvaluationPlan`、万能 `StageResult`、通用评分表、评价纪元、复杂度分数或自动策略工厂。工程正确性由测试与 Release 验收证明，投资有效性由市场和账户 evaluator 证明，两者不共用一个 `PASSED`。

## 3. 身份不能成为逃避证据的工具

行为身份由各领域拥有并按依赖组合，不存在一个修改任意代码就整体换代的全局行为 ID。Forecast 行为引用其实际依赖的 WorldModel、输入和合同身份，资本行为再引用 Forecast、产品、Portfolio 与 Risk 行为；上游实质变化只让真实依赖它的下游结果换代。代码整理、Dashboard、日志、恢复和其他行为无关 Release 不能重置 cohort；模型、Prompt、输入投影、工具、ForecastContract、触发采样或资本政策实质变化时，受影响的未来事实必须使用新身份，旧成绩不得继承。

每个会搜索 Alpha 或组件增量的问题还必须拥有稳定 `evaluation_family_id`。它由 objective、Mandate、被评价层、决策作用域和 Outcome 定义确定，不由自然语言假设、候选名称、Release、基线版本或 Agent 自行命名。改变 Prompt 措辞、阈值、特征、模型、数据源、实现方式、Reference 或 evaluator，只要仍回答同一个经济问题，就仍保留在原评价家族；考试坐标变化另行版本化并使不可比结论失效，不能重置搜索历史。

任何可能改变 PortfolioTarget 的候选，无论最初来自数据、认知、Forecast、产品还是 Portfolio，同时都属于该 Mandate 唯一的资本政策评价家族；组件家族只能回答该组件是否值得存在，不能把资本候选拆成多个局部家族分别取得交易资格。这样允许同一事实承担可辨识的组件诊断，却只在总资本家族中承担一次权限裁决。

家族历史从全部已登记合同及其终态结果派生，包含失败、证据不足、失效、运行失败和已查看结果的候选；不另建可被遗漏的 `FailedExperiment` 记忆。Agent 输入可以使用有损摘要控制容量，但治理 Gate 必须查询完整耐久历史，不能只看最近若干条。已观察的样本永久转为开发信息，不能因换名、换 Release、修改窗口或重新登记再次证明该家族的候选；同一活动合同只有事前冻结了 anytime-valid 更新和停止规则时，才可以在查看中间结果后继续接收新样本。

## 4. 一份问题只有一个考试合同和 evaluator

候选在读取相应结果前，由问题所属领域冻结类型化评价合同。所有合同只共享稳定 ID、`evaluation_family_id`、登记时间、内容哈希、行为身份、evaluator 身份、状态和废止引用；其余内容由该问题定义。一份改变投资行为的合同至少冻结：

- 适用 Mandate、Reference Policy、合法产品和行为身份；
- base/candidate 行为或制品内容身份、一个主要因果主张、实际差异、保持不变项以及无法拆分时的理由；
- 输入截止、样本来源、完整样本终态、缺失和运行失败处理；
- 唯一主基线、主指标、必要诊断、成本和数据查询身份；
- 时间依赖或非重叠处理、成功、失败、证据不足和硬停止规则；
- 评价家族历史所采用的搜索修正协议；
- 实验资本、最大累计损失、有效期、撤销和候选删除条件。

合同终态只有 `PASSED`、`FAILED`、`INCONCLUSIVE` 或 `INVALIDATED`。`INCONCLUSIVE` 不能延期、改指标或换名变成通过；`INVALIDATED` 只表示评价坐标存在确定性缺陷，并保存影响范围，不能伪装成候选失败，也不能追溯授予权限。

候选生产者只能写业务输出，不能写评价结果。唯一 evaluator 按冻结查询从原始事实重建样本并计算终态；权限层只接受 evaluator 的内容身份，不接受字符串指标、Dashboard 汇总或候选提交的 `PASSED`。能够精确重建的评分、成本、统计与 Gate 必须确定性计算；若未来某类不可结构化评价确实需要 AI，AI evaluator 也必须拥有独立冻结身份、可重放输入和自身有效性证据，且不能与候选是同一行为或直接写权限。修改 Mandate、Reference Policy 或 evaluator 与修改 Alpha 候选必须是不同变更，不能一边降低考试标准一边让候选晋级。

评价完整性依赖执行隔离而不是隐藏评分规则。候选可以知道合同和指标，但 evaluator 必须从登记时冻结且位于候选写入与导入闭包之外的制品启动，以只读查询重建点时事实；候选只能提交其行为制品和业务输出，不能覆盖 evaluator、测试分割、查询截止、Reference 或结果存储。历史 blind 的未揭示事实必须拒绝候选进程访问，一次性 claim 和访问审计属于该领域 evaluator；真实未来 Outcome 天然在候选完成后产生。Evaluator 哈希、实际输入集合、文件或事实访问违约与重算结果一并成为评价完整性事实：能够归因于候选的越权或篡改尝试使候选 `FAILED`，执行环境自身无法证明隔离与输入完整性才使合同 `INVALIDATED`；二者都不能被折算成普通指标扣分。

每个评价家族只采用一种与采样方式匹配的错误控制协议：

- 当前低频系统默认串行评价一个 challenger；每个后来候选只能用登记后的新事实取得评价资格，并按家族事前冻结的递减错误预算或等价 online 规则裁决，既有事实仍可用于开发但不能再次证明候选；
- 能在同一冻结样本上同时计算的有限候选族，使用 Reality Check、Model Confidence Set 或等价的联合多重比较；
- 只有真实存在持续候选流和持续监控需要时，才升级为基于 e-value/e-process 的 online 或 anytime-valid 方法，并冻结所有候选共享的信息过滤；
- 历史 blind 只允许一次，用于程序化研究的额外否决，不能证明 AI Alpha，也不能替代未来市场结果。

不得叠加多套统计协议制造仪式感，也不得从多个合法检验中事后选择最容易通过的一个。最低样本数只决定何时允许评价，不代表证据充分；不确定性、时间跨度、依赖簇、覆盖率和压力结果仍必须满足冻结标准。

## 5. 评价只回答两类价值问题

### 5.1 完整资本政策是否值得资金

资本权限只看完整政策在相同 Mandate、同期可投资事实、外部现金流、风险预算和现实成本下，是否相对唯一、冻结、简单且可执行的 Reference Policy 产生可靠的费用后增值，并同时满足绝对复利、回撤、尾部和压力后流动性约束。

Reference beta、主动偏离以及 Risk/Execution/成本造成的保留或损耗分别展示，但最终只有一条可对账的总组合反事实和真实账户结果。相对现金、单资产被动暴露、模拟 PnL 和组件分数只是诊断；没有合格 Reference Policy 时，总组合盈利考试尚未开始。回放证明实现与历史适配，Mock 证明链路和模拟经济性，真实资本扩大必须依赖 Forecast 可用后真实 Venue 的订单、成交、费用、账户和风险结果。

### 5.2 可选组件是否值得存在

组件评价只用于归因和删除复杂度，不直接授予资本：

| 组件 | 唯一问题与对照 |
|---|---|
| Evidence/State | 点时完整性、准确性和相对无该输入的增量 |
| WorldModel | 同槽、同模型、同截止的有/无认知前瞻配对 |
| TriggerPolicy | cadence-only 与 cadence+event 的同风险费用后逻辑账户 |
| Forecast | proper score、校准、覆盖率和动态简单基线 |
| Product mapping | 消去规范经济参考实际收益后的 basis、funding 与规则残差 |
| Portfolio | 相对不含该复杂组件的最简单可执行组合政策 |
| Execution | 从冻结目标和决策价格开始的 implementation shortfall |

派生组件必须先消去可观察的上游现实贡献；做不到时只能评价整条政策，不能把混合误差归给某一层。完整政策盈利不能证明全部组件有用，组件分数改善也不能证明值得交易。组件没有稳定增量时删除该组件；组件有效但总组合没有增量时，只保留研究资格。

## 6. 样本完整性与失败语义

Cadence 必须持续产生 Forecast 或明确的 `NO_ESTIMATE`，并结算现金、持有、拒绝、未交易和错失机会；材料事件槽不能消费固定 cadence。共同事件和重叠时域按冻结规则形成依赖簇，不能按调用次数增加样本。

每个 evaluator 定义自己的完整样本终态。部分 projection、缺少 PortfolioTarget 的 Forecast、未闭合资本处置、只有成功一侧的配对、未决订单或不完整账户都不能进入相应价值统计，只进入覆盖率、恢复和失败事实。运行失败不是自动负收益，也不能被删除：只有合同能事前定义可识别的保守惩罚；否则结果为 `INCONCLUSIVE`，并由运行可靠性评价负责。

机会成本必须来自事前已冻结且当时合法可执行的候选或基线，不能从事后看到的上涨区间倒推。产品映射、Forecast、Portfolio 和 Execution 可以读取同一经济过程，但同一误差只能由一个权威 evaluator 裁决一次。

## 7. 权限是有期限的结果引用

所有能产生新风险的运行都必须持有 `Authorization`。为收集证据的权限引用评价合同；保留或扩大资本的权限引用已通过且未废止的资本评价结果。权限冻结适用行为、产品、方向、账户、资本和风险包络、最大累计损失、有效期、退化条件及撤销动作。

样本不足、行为身份改变、结果过期、账户不一致或损失边界越过时停止新增风险，只允许恢复、对账或减险。权限不因曾经通过自动续期，也不能从组件评价、模拟收益或工程测试推导。持续有效性直接复用该权限所引用 evaluator 的新增 Outcome 流和预登记风险/损失边界，只产生“继续有效”或“停止新增风险”，不建立第二个漂移评分系统；普通特征漂移或 Agent 命名的 market regime 只能触发诊断，不能自行撤权、重置历史、调参或授予新行为。若合同明确冻结了超出支持域的可验证条件，它可以保守撤权；任何自适应时间窗、衰减权重或变化点规则也必须在读取相应结果前冻结。安全硬约束始终可以减少风险，但不能创造 Alpha 或扩大仓位。

同一作用域同时只有一个正式资本实现。Shadow 对照可以并存，但只写评价事实，不能双写账户或成为隐藏 fallback。被替代行为切换完成后删除运行路径；不可变历史保留，但不能重新获得执行资格。

## 8. Agent 的最小闭环

主 Agent 每次从现役领域事实按任务派生最小证据视图，只提供当前 Mandate、Reference、行为、评价合同与结果、家族搜索摘要、权限和运行异常的内容引用。该视图不持久化、不读取 `legacy`、不复制指标，也不通过常驻 Governor Worker 自动提案；完整家族历史由确定性 Gate 在数据库侧校验，不靠把所有记录塞进 Prompt。

Agent 每次只做以下工作：

1. 选择对资本价值影响最大的可验证断点；
2. 提出一个能被明确事实推翻的最小变更，或选择不变更；
3. 在干净基线上实现候选，不修改其 evaluator、Reference 或历史事实；
4. 等待独立评价终态；
5. 通过则只获得结果允许的未来权限，失败则删除候选代码，证据不足则不追加补丁。

默认每个评价家族只运行一个 challenger。不同家族的候选只要修改同一领域行为、共享同一正式资本路径，或使彼此的样本与反事实发生变化，也必须串行或合并成一份不可分割合同；Gate 直接比较合同已经冻结的行为依赖和资本作用域，不为此建立冲突图。只有长期真实并发需求证明该判断成为主要瓶颈时，才引入更复杂的分配；当前不建设租约系统、多 Agent 辩论、元优化器或自动资源市场。Evaluator 对结构化事实使用确定性增量计算，只处理新终态事实。

## 9. 必须阻断的自欺路径

- **少量盈利：** 保守下界、时间覆盖或 Reference 增量不足时保持 `INCONCLUSIVE`。
- **换名重试：** 相同经济问题仍属于原 `evaluation_family_id`，已看样本不能重用。
- **持续发版无样本：** 行为无关 Release 保留 cohort；行为变更等待原合同终态，确定性缺陷则显式 `INVALIDATED`。
- **修改考试坐标：** Mandate、Reference 或 evaluator 变更立即废止受影响权限，但不能帮助同一候选晋级。
- **事件密集制造样本：** 相关 Forecast 按时间和事件簇处理，调用次数不进入证据门槛。
- **解释改善冒充 Alpha：** WorldModel 只有同时改善同槽 Forecast 且其主动偏离改善资本结果，才可以声称协助盈利。
- **模拟盈利冒充实盘：** 页面必须按证据层明确标注；Mock、Shadow 和回放不得使用“已证明盈利”语义。
- **评价器投机：** 不存在候选能够写入的通用奖励或通过字段；Gate 从完整历史和原始事实独立重算。
- **市场状态变化：** 旧证据永久保留，预登记有效性边界只撤销旧权限；新状态解释和自动调参都必须作为新行为重新评价。

## 10. 完成标准

系统只有同时满足以下条件，才具备可信而高效的自演进能力：

- 任一候选都能映射到稳定评价家族，Gate 使用完整历史而非 Prompt 中的有限记忆；
- 每个问题只有一个类型化合同、一个 evaluator 和一份权威结果，候选不能写自己的结论；
- evaluator 从候选无法覆盖的冻结制品和只读点时事实运行，未揭示数据访问与结果完整性可审计；
- 行为身份按领域依赖组合且与 Release 解耦，无关发版不重置样本，实质变更只让受影响路径换代且不继承成绩；
- 已观察数据不再成为 blind/forward 证据，运行失败和不完整样本不能选择性消失；
- 概率预测、产品映射、组合选择和执行分别评价且不重复归因；
- 总组合资本权限只读取相对唯一 Reference Policy 的前瞻、费用后、风险调整结果；
- 每项权限有资本包络、有效期、退化条件和可执行撤销动作；
- 失败或被替代的生产代码已经删除，历史只保留不可执行事实；
- 长期增加候选和 Release 不会增加评价真相、投资链或状态机数量；
- 系统能够合法输出没有赢家，并且 Agent 可以长期选择不变更。

满足这些条件只说明系统能够降低研究过拟合并可靠淘汰较差行为，不代表已经找到 Alpha。稳定盈利仍只能由持续、点时、前瞻、费用后、风险调整且可对账的真实账户结果证明。

## 11. 方法依据

- [Strictly Proper Scoring Rules](https://doi.org/10.1198/016214506000001437) 与 [2026 年综述](https://doi.org/10.1146/annurev-statistics-042424-050626)：概率分布必须使用 proper score 评价，不能由方向命中或点误差替代。
- [The Implementation Shortfall](https://doi.org/10.3905/jpm.1988.409150)：执行评价从投资决策时点开始，计入成交、延迟、显性成本和未成交机会。
- [Reality Check for Data Snooping](https://doi.org/10.1111/1468-0262.00152) 与 [Model Confidence Set](https://doi.org/10.3982/ECTA5771)：候选搜索历史必须进入比较，并允许没有赢家。
- [Online multiple testing with e-values](https://proceedings.mlr.press/v238/xu24a.html)：持续出现的候选需要控制全局错误发现，而不是让每个候选单独通过固定阈值。
- [Adaptive Learn-then-Test](https://proceedings.mlr.press/v267/zecchin25a.html)：2025 年工作说明 e-process 可以在保持有限样本保证时减少自适应候选的测试成本；本项目只在真实持续候选流出现后采用，不把它预建成平台。
- [Testing by Betting](https://doi.org/10.1017/9781108914964) 与 [Comparing Sequential Forecasters](https://arxiv.org/abs/2110.00115)：持续监控必须使用事前确定、与共同信息过滤一致的 anytime-valid 规则。
- [LLMs Cannot Self-Correct Reasoning Yet](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html)：没有外部可验证反馈的语言反思不能提供可靠自我纠错。
- [Hidden Technical Debt in Machine Learning Systems](https://proceedings.neurips.cc/paper_files/paper/2015/file/86df7dcfd896fcaf2674f757a2463eba-Paper.pdf)：重复消费者、反馈回路和边界侵蚀会形成系统级技术债，因此评价事实必须保持单一所有者。
- [SWE-Gym](https://proceedings.mlr.press/v267/pan25g.html)：可执行环境和独立 verifier 有助于筛选软件 Agent；测试证明工程正确性，市场与账户 Outcome 才能证明投资有效性。
- [Model Assessment and Selection under Temporal Distribution Shift](https://proceedings.mlr.press/v235/han24b.html)：非平稳环境中的比较依赖事前定义的时间自适应方法，不能在看到近期表现后任意选择最有利窗口。
- [On Continuous Monitoring of Risk Violations under Unknown Shift](https://proceedings.mlr.press/v286/timans25a.html)：部署后的持续风险保证需要控制误报的序贯规则；本项目只把它用于保守撤权，不把漂移告警转化为 Alpha。
- [Honesty to Subterfuge](https://doi.org/10.48550/arXiv.2410.06491) 与 [Reward-HackingAgents](https://arxiv.org/abs/2603.11337)：迭代反馈和可写评价环境会让 Agent 发现规格投机、评价器篡改或测试泄漏路径，因此候选与 evaluator、未揭示事实和权限写入必须在执行上隔离。

最终原则：**Agent 扩大可证伪候选的搜索，评价家族约束搜索自由度，独立 evaluator 决定证据，现实资本结果决定权限，仓库只保留仍被需要的运行机制。**
